# 팀 지식 위키

이 저장소(insulation-partition-generator — 단열 Layout 런처)의 지식 창고입니다. 구조와 규칙은 Woomi 코딩 에이전트 템플릿 2.27-draft 에서 가져왔습니다. 저장소 규칙을 그래프로 탐색하고, 팀이 배운 것을 여기에 쌓습니다.

## 여는 법

이 폴더(`wiki/`)를 두 가지로 엽니다.

- **옵시디언** — `Open folder as vault` 로 `wiki/` 폴더를 고릅니다. 사람이 보는 창입니다. 그래프 뷰에서 규칙들이 어떻게 연결되는지 보입니다.
- **Claude Code** — 저장소 루트를 그대로 엽니다. AI가 읽고 쓰는 손입니다.

둘이 같은 파일을 봅니다. 한쪽에서 고치면 다른 쪽에 바로 보입니다.

## 안에 든 것

```txt
wiki/
  README.md      ← 이 파일 (구조와 규칙)
  index.md       ← 내용 카탈로그
  log.md         ← 시간순 append-only 기록
  CLAUDE.md      ← AI가 이 폴더에서 일할 때의 규칙
  sources/       ← 원본을 가리키는 출처 기록 — 읽기만 한다
  rules/         ← 저장소 규칙(.agents/*)의 정리본
  systems/       ← 화면·코드 경로 — 어디를 지나 어떻게 동작하는가 (생기면 만든다)
  patterns/      ← 반복되는 실패 양상 — 같은 실수를 또 하지 않기 위해 (생기면 만든다)
  _templates/    ← 페이지 템플릿 (rule · system · pattern)
```

**`systems/` 와 `patterns/` 는 빈 폴더로 두지 않습니다.** 이 저장소에는 아직 `systems/`·`patterns/` 페이지가 없습니다(2026-10-21 도입 시점). 화면·경로 지식이나 두 번 이상 반복된 실패가 정리될 때 만듭니다.

| 폴더 | 무엇 | 규칙 |
|---|---|---|
| `sources/` | 원본을 가리키는 출처 기록 | 읽기만 합니다. 저장소 규칙이 원본이면 `.agents/*`에서만 고칩니다. **예외 — `정리한 노트:` 줄은 색인이므로 갱신합니다** |
| `rules/` | 규칙 정리본 | 원본을 압축합니다. **자주 바뀌는 목록(테이블 카탈로그·엔드포인트 목록)은 복사하지 말고 원본을 가리킵니다** — 복사하면 두 곳이 갈라지고, 그게 이 템플릿의 최대 실패 모드입니다 |
| `systems/` | 화면·경로별 지식 | 저장 구조와 "데었던 것"을 커밋 SHA 와 함께 남깁니다 |
| `patterns/` | 반복 실패 양상 | **사례가 2건 이상 모였을 때만** 만듭니다. 1건이면 해당 시스템/규칙 페이지의 절로 둡니다 |
| `log.md` | 언제 무엇을 왜 | 덧붙이기만 합니다 |
| `index.md` | 페이지 목록 | 페이지를 고치면 같이 갱신합니다 |

## 단위가 핵심입니다

**소스 하나당 페이지 하나를 만들면 지식이 쌓이지 않습니다.** 같은 실패가 세 화면에서 나왔으면 세 페이지에 세 번 적는 게 아니라 패턴 하나로 접습니다 — 다음에 네 번째 화면에서 만났을 때 찾을 수 있는 형태는 그쪽입니다.

가치는 `rules/`·`systems/`·`patterns/` 에 있고, `sources/` 는 그 페이지들이 어디서 왔는지를 밝히는 재료입니다.

## 페이지마다 frontmatter를 답니다

정리본(`rules/`·`systems/`·`patterns/`)과 위키 자체 문서(`index`·`log`·`README`·`CLAUDE`)는 이 형식입니다.

```yaml
---
type: rule | system | pattern | index | log | schema
updated: YYYY-MM-DD
tags: [area/…, domain/…]
---
```

`updated` 는 **내용이 마지막으로 바뀐 날**입니다. 파일 이동·형식 정리처럼 내용이 그대로인 변경에는 갱신하지 않습니다. 원본(`.agents/*`)의 최종 수정일보다 정리본의 `updated` 가 오래됐으면 낡았는지 의심할 자리입니다.

### `sources/` 는 형식이 다릅니다

원본 기록은 **넣은 뒤 고치지 않는 것**이 규칙이라 `updated` 가 의미를 갖지 않습니다. 대신 넣을 때의 사실을 적습니다.

```yaml
---
type: source
원본: ../../.agents/…  또는  자료 이름
넣은날: YYYY-MM-DD
목적: 왜 모았는지 (`/wiki-add-source` 1단계에서 받은 답)
---
```

`tags` 도 달지 않습니다 — 원본은 탐색 대상이 아니라 정리본의 근거입니다. 본문 아래에는 `정리한 노트:` 줄을 두어 어느 정리본이 이 원본에서 나왔는지 가리킵니다. **이 줄만은 갱신합니다**(아래 표의 예외).

> 이 절은 2026-09-13 점검에서 추가됐습니다. 그전에는 위 문단이 "모든 페이지"라고 적혀 있었는데 `/wiki-add-source` 는 원본에 `원본`/`넣은날`/`목적` 만 적으라고 지시하고 있어, `sources/` 24개 전부가 명령을 따르고 README 를 어긴 상태로 보였습니다. **명령이 맞고 README 가 틀렸던 것**이라 README 를 고쳤습니다.

## 네 가지 명령

저장소 루트에서 Claude Code 슬래시로 부릅니다. **한 번에 하나씩** 보냅니다.

| 명령 | 언제 |
|---|---|
| `/wiki-add-source` | 자료를 넣을 때. 왜 모으는지 먼저 묻습니다 |
| `/wiki-ask` | 쌓인 것에서 찾아 답받을 때. 출처가 같이 붙습니다 |
| `/wiki-log-today` | 하루 마무리 5분. 오늘 한 것을 남깁니다 |
| `/wiki-check` | 위키가 성한지 볼 때. 끊긴 링크와 색인 어긋남을 잡습니다 |

**에이전트가 먼저 챙깁니다.** `wiki/`가 있는 프로젝트에서는 명령을 부르지 않아도, 에이전트가 작업 전 위키를 찾아보고 남길 것이 생기면 남기자고 먼저 제안합니다. 위키를 쓰지 않으려면 `wiki/` 폴더를 지웁니다. (규칙: [`AGENTS.md`](../AGENTS.md) §1)

## 여기 무엇을 쌓나

- 저장소 규칙(`.agents/*`)의 정리본과 연결 지도
- 잘 통한 프롬프트와 하네스 설정
- 막혔다 푼 것과 그 해결책
- 정한 것과 왜 그렇게 정했는지
- 자주 참조하는 사내 규정·양식

**넣기 전에 왜 모으는지 답할 수 있어야 합니다.** 목적 없이 쌓으면 파편만 늘어납니다.
**출처를 아는 자료만 넣습니다.** 밖에서 받은 문서를 AI가 다시 읽는 구조이기 때문입니다.

## 규칙 문서와의 관계

`.agents/*`와 `AGENTS.md`가 권위 있는 규칙입니다. 이 위키는 그 규칙의 **탐색·축적 레이어**입니다. 둘이 어긋나면 `.agents/*`가 이기고, 위키를 고칩니다. 규칙 자체를 바꿔야 하면 `.agents/*`를 고치고 `AGENTS.md` 10장에 따라 `CHANGELOG.md`를 갱신합니다.
