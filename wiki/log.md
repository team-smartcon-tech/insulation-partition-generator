## 2026-08-14 · 정하기·만들기 · 신규 사용자 온보딩(`/onboard`)과 git 승인 경계 재정의

- 한 것: 처음 온 비개발자를 첫 커밋까지 데려가는 `/onboard` 명령 추가. `AGENTS.md` §6의 git 승인 규칙을 작업 성격으로 나눔. `.claude/settings.json`에 로컬 git 작업 allowlist 신설. `QUICKSTART.md`의 `git init` 누락 수정. (2.12 → 2.13-draft)
- 정한 것과 이유:
  - **온보딩 종료 조건은 PR이 아니라 로컬 커밋 1개.** 공식 도입 경로가 ZIP 다운로드라 원격 저장소가 없다 — PR을 넣으면 GitHub 계정 만들기가 온보딩 안으로 들어와 온보딩이 GitHub 강좌가 된다. 단 브랜치 생성은 포함한다. 안 하면 `main`에서 커밋하게 되고 첫 푸시에서 반드시 차단당한다.
  - **`SessionStart` 훅을 만들지 않는다.** `CLAUDE.md`는 세션 시작 시 자동으로 읽히므로, 거기 한 줄 넣으면 훅 없이 같은 효과가 난다. 사용자가 "이거 뭐하는 폴더냐"고만 물어도 에이전트가 `/onboard`로 유도한다.
  - **git 승인 경계를 "승인 여부"가 아니라 "되돌릴 수 있느냐"로 나눈다.** 로컬 작업은 사전 승인, 저장소 밖으로 나가는 것만 한 줄 안내. 커밋을 매번 승인받게 하면 오히려 커밋을 미루게 되어 작업 유실 위험이 커진다.
  - **`scripts/agent-guard.cjs`와 `.githooks/`는 손대지 않는다.** 조사해 보니 하드 차단은 원래 되돌릴 수 없는 것(main 푸시, `--no-verify`, `reset --hard` 등)만 골라 막고 있었다. 평범한 `git commit`과 피처 브랜치 푸시는 처음부터 통과했다 — 마찰의 정체는 차단이 아니라 승인 규칙과 권한 프롬프트였다.
  - **allowlist는 `.claude/settings.local.json`이 아니라 추적되는 `.claude/settings.json`에 넣는다.** `CLAUDE.md`의 금지 규칙은 유지 — 금지 이유가 "리뷰에 안 보이는 곳에서 승인이 사라지는 것"이므로, PR에서 보이는 곳에 명시하면 그 이유에 저촉되지 않는다.
  - **실습 과제로 `dashboard.tsx`의 숫자를 쓰지 않는다.** 같은 값이 21~26행과 63~86행 두 곳에 있고 실제 렌더링은 아래쪽이다. 비개발자가 위를 고치면 화면이 안 바뀌어 첫날에 신뢰를 잃는다. 대신 `_app.tsx`의 사이드바 브랜드명을 쓴다 — 모든 화면에 보인다.
- 막혔다 푼 것:
  - "온보딩 문서가 없다"고 보고 새로 쓰려 했으나, `QUICKSTART.md`에 이미 AI 주도 프롬프트 A/B가 있었다 → 실제 결손은 문서가 아니라 **비개발자 경로의 단절 3개**(`git init` 누락 / GitHub 저장소 만드는 안내 0회 / 차단은 있는데 PR 만드는 법이 없음)였다. 조사 없이 만들었으면 있는 것을 또 만들 뻔했다.
  - `AGENTS.md` §6을 고치자 `.agents/WORKFLOW.md`와 위키 정리본 3개에 옛 규칙이 남아 모순이 생겼다 → 같은 작업에서 전부 동기화. 규칙을 고칠 때 어디가 그 규칙을 복제하고 있는지 먼저 grep해야 한다.

## 2026-09-09 · 만들기 · 우미 양식 모음집 — 엑셀을 격자 그대로 읽는 변환기

- 왜 만드나: 사내 업무 양식(엑셀)을 올리면 **원본 모양 그대로** 화면에 뜨고 빈 칸을 채워 저장하는 도구. 홈의 "새 아이템" 카드를 이걸로 교체한다. 1차 프로토타입이 있었으나 엑셀을 "항목명+선택지" 리스트로 바꾸는 방식이라 반려됐다 — 요구는 **셀 병합을 포함한 양식 그대로의 재현**이었다.
- 정한 것과 이유:
  - **엑셀 파싱은 `xlsx`(SheetJS)가 아니라 `exceljs`로 한다.** 이 저장소에는 이미 `xlsx` 가 있지만(공지사항·물량 내보내기에서 사용) 무료판은 셀 스타일(색·테두리·글꼴)을 읽지 못한다. 병합만 필요하면 `xlsx` 로 충분한데, 요구가 "색·테두리까지 최대한"이라 스타일을 읽는 `exceljs` 를 **추가로** 넣었다. 두 라이브러리가 공존하지만 용도가 갈린다 — 내보내기는 `xlsx`, 양식 읽기는 `exceljs`.
  - **`exceljs` 는 최상단이 아니라 파싱 시점에 동적 import 한다.** 약 1MB라 양식 화면에 안 들어오는 사용자까지 비용을 내면 안 된다. 이미 번들이 10MB인 상황이라 더 늘리지 않는 쪽을 골랐다.
  - **병합은 `model.merges` 문자열을 파싱하지 않고 각 칸이 알려주는 `master` 주소로 모은다.** 같은 결과를 두 경로로 얻을 수 있는데, `master` 는 셀에서 직접 나오므로 exceljs 내부 표현이 바뀌어도 덜 흔들린다.
  - **입력칸 기본값은 "원본이 비어 있으면 입력칸"으로 하되 그것만으로는 안 된다.** 받은 샘플(`apps/worker/samples/단속점검방문일지양식.xlsx`)이 **빈 양식이 아니라 다 채워진 예시**였다 — 공사명·건축주·시공자·면적·방문기간·현장대리인에 실제 값이 들어 있고 진짜 빈 칸은 3개(③④⑤)뿐이었다. 규칙을 그대로 적용하면 매번 바뀌어야 할 항목이 고정 글자로 굳는다. 그래서 자동 판정을 기본값으로 두고 **관리자가 칸을 켜고 끄는 편집 모드**를 얹기로 했다. `FormCell.key`(대표 칸 좌표)가 그 지정을 붙일 자리다.
  - **서식만 남은 빈 껍데기 칸은 시트 범위를 넓히지 않는다.** 샘플의 `columnCount` 는 8인데 8열에는 정렬 속성만 있는 칸(H19)이 하나 있었다. 값·테두리·채우기 중 아무것도 없으면 범위에서 뺀다 — 안 그러면 표 오른쪽에 빈 열이 붙는다.
- 배운 것: **"양식 파일을 넣어놨다"를 받으면 그게 빈 양식인지 작성 완료본인지부터 본다.** 이 차이가 입력칸 판정 규칙 전체를 뒤집었고, 파서를 다 만든 뒤에 알았으면 규칙을 다시 설계해야 했다. 파싱 결과를 눈으로 덤프해 본 것이 그 앞에서 막아 줬다.
- 회귀 방지: `tests/form-parser.test.mjs` 가 실제 양식으로 **각 행의 `colSpan` 합 = 전체 열 수**를 확인한다. 병합 처리가 어긋나면 표가 통째로 밀리는데 눈으로는 늦게 발견된다.
- 화면 1차(읽기 전용)에서 더 정한 것:
  - **동적 import 가 실제로 값을 했는지 프로덕션 빌드로 확인했다** — `exceljs.min-*.js` 936kB 가 별도 청크로 갈리고 메인 번들은 +12kB 만 늘었다. "동적 import 했으니 괜찮겠지"로 넘기면 번들러 설정에 따라 그대로 합쳐질 수 있어, 청크 목록을 눈으로 봐야 확인된 것이다.
  - **글꼴 크기는 pt 를 px 로 환산하지 않고 `pt` 그대로 CSS 에 넘긴다.** CSS 가 pt 를 지원하므로 환산할 이유가 없고, 환산하면 셀마다 반올림 오차가 쌓여 원본과 미세하게 어긋난다. 반대로 행 높이·열 너비는 엑셀 고유 단위(문자폭/pt)라 px 로 바꿀 수밖에 없다.
  - **한글 글꼴은 계열을 지켜 대체한다** — `바탕`(명조)이 없는 PC 에서 고딕으로 떨어지면 공문서 느낌이 크게 달라진다. 바탕·궁서는 `serif`, 굴림·돋움·맑은고딕은 `sans-serif` 로 폴백을 나눠 뒀다.
  - **자동 판정된 입력칸을 화면에서 색으로 표시하는 토글을 넣었다.** 이 단계의 목적이 "판정이 맞는지 눈으로 보는 것"이라, 표시가 없으면 확인할 방법이 없다.
- 아직 안 한 것: 저장·불러오기, 그리고 프로토타입에 있던 폴더/즐겨찾기/검색 구조. `systems/` 정리본은 화면이 확정되는 단계에서 만든다(지금은 임시 화면이라 문서가 코드보다 먼저 낡는다).

  - **"어디까지 자동으로 해줄까"를 물을 때 "전부 수동"도 선택지에 올려야 한다.** 첫 질문에서 "모든 칸 편집 가능"을 제시했지만 "실수로 양식 글자를 지울 수 있음"이라는 단점만 달아 두었다. 그 단점은 실제로는 사소했고(원본으로 되돌리기 버튼 하나면 된다), 자동 판정의 비용이 훨씬 컸다.
  - **되돌릴 수 있게 만들어 두면 방향 전환이 싸진다.** 걷어낸 방식을 지우기 전에 커밋(`f202b12`)해 뒀다. 되살릴 일이 생기면 파일 하나 되돌리면 된다.
- 남긴 것: 파서(`formParser.ts`)는 그대로다 — 격자·병합·스타일을 읽는 부분은 어느 방식이든 필요하다. 뒤집힌 것은 "그 위에서 무엇을 입력칸으로 볼까" 하나뿐이었다. **경계를 잘 그어 둔 덕에 방향 전환이 화면 쪽에서만 끝났다.**
- **찾은 버그 — 병합 칸의 바깥 테두리가 통째로 사라졌다.** 엑셀은 테두리를 **칸마다 따로** 저장한다. `B11:G11` 병합이면 오른쪽 선은 대표 칸 `B11` 이 아니라 맨 오른쪽 `G11` 에 들어 있다. 대표 칸에서만 읽으니 병합된 줄마다 오른쪽 선이 빠졌고, 양식 오른쪽 테두리가 없는 것처럼 보였다. **병합 범위의 네 모서리 칸에서 각각 읽어야 한다** — 위·왼쪽은 좌상단, 오른쪽은 우상단, 아래는 좌하단. `tests/form-parser.test.mjs` 에 회귀 테스트를 넣었다.
- **엑셀의 "자동 줄바꿈" 설정을 무시하면 한 줄짜리 항목이 쪼개진다.** 모든 칸을 접도록 그렸더니, 줄바꿈이 꺼진 칸(`소속: … 직급: … 성명: … (서명 또는 날인)`)이 두 줄로 갈렸다. 엑셀 설정을 그대로 따르고, 접지 않는 칸이 넘칠 때는 글자를 조금씩 줄여 맞춘다(엑셀 "축소하여 맞춤"과 같은 처리). 같은 "바탕 11pt" 라도 엑셀과 브라우저의 글자 폭이 달라, 원본에서 한 줄에 들어가던 것이 여기서는 넘칠 수 있기 때문이다.
- **열 너비 환산은 기본 글꼴에 달려 있다.** 흔히 쓰는 `너비 × 7px` 은 Calibri 11pt 기준이다. 국내 양식은 바탕·굴림 계열이라 숫자가 더 넓어, 7 로 환산하면 실제보다 좁아져 제목이 원본보다 더 접힌다. 8 로 올렸다 — **좁아서 줄이 깨지는 쪽이 넓어서 여백이 남는 쪽보다 훨씬 눈에 띈다.**
- **못 고친 것 — 셀 안의 수동 줄바꿈은 일반 규칙으로 정리할 수 없다.** 같은 양식 안에서도 `④ 업무 수행내\n용`(단어 중간)과 `③ 방문근거\n및 목적`(어절 경계)이 섞여 있다. 앞은 공백 없이 붙여야 하고 뒤는 공백을 넣어야 하는데, 한글은 단어 사이에 공백이 없어 둘을 구분할 방법이 없다. 사전 없이는 판정이 불가능하므로 **사람이 그 칸을 고치는 쪽이 맞다** — 모든 칸이 편집 가능하므로 한 번 고치고, 양식 저장 기능이 생기면 그 상태로 재사용한다.
- 화면 쪽 판단: 편집 상자는 평소에 보이지 않게 했다(테두리·배경 없이 원본 글자와 똑같이 보이다가 올리거나 누를 때만 표시). 칸이 100개 가까이 되는데 전부 입력 상자처럼 보이면 "양식"이 아니라 "입력 폼"으로 읽힌다. 글이 길어지면 칸이 함께 늘어나도록 textarea 높이를 내용에 맞춰 조정한다.

## 2026-09-10 · 만들기 · 올린 양식을 브라우저에 남긴다(IndexedDB)

- 무엇을 만들었나: 올린 엑셀과 고쳐 적은 글자가 **새로고침·재접속 후에도 남는다**. 저장된 양식 목록에서 골라 열고, 지울 수 있다. `apps/web/src/features/forms/formStore.ts`.
- **왜 localStorage 가 아니라 IndexedDB 인가:** localStorage 는 문자열만 담고 용량이 5MB 안팎이라 엑셀 원본 바이트를 넣을 수 없다. IndexedDB 는 `ArrayBuffer` 를 그대로 담고 용량도 훨씬 크다. 다만 "마지막에 보던 양식 id" 같은 화면 상태는 작아서 localStorage 로 남긴다 — 저장 계층을 하나로 통일하는 것보다 크기에 맞게 나누는 쪽이 단순하다.
- **원본 바이트와 파싱 결과를 함께 담는다.** 파싱 결과만 담으면 다시 열 때 빠르지만 파서가 좋아져도 옛 모양 그대로 굳는다. 원본만 담으면 열 때마다 `exceljs`(936kB 청크)를 다시 내려받는다. 둘 다 담고 `PARSER_VERSION` 이 올라간 것만 다시 읽어 덮어쓴다 — **테두리·열 너비처럼 이미 세 번 고친 부분이 있어, 저장한 양식이 옛 파서에 묶이는 것은 실제로 일어날 일이었다.**
- **사용자가 고친 글자(`values`)는 셀 키에 붙어 있어 다시 파싱해도 살아남는다.** 키를 좌표(`행:열`)로 잡아 둔 덕이다. 값을 배열 순서로 저장했으면 파서가 칸 하나를 더/덜 잡는 순간 전부 밀렸다.
- **값 저장은 읽기·쓰기를 한 트랜잭션에 묶었다.** `get` 한 결과에 값만 바꿔 `put` 하는데, 이걸 두 트랜잭션으로 나누면 그 사이 다른 탭이 쓴 내용(원본 바이트·격자)을 덮어쓴다. 같은 화면을 두 탭에 띄우는 것은 실제로 흔하다.
- **저장이 막힌 브라우저에서도 화면은 살려 둔다.** 시크릿 창이나 사이트 데이터 차단이면 `indexedDB` 접근 자체가 던진다. 그때는 경고만 띄우고 양식 작성은 그대로 되게 했다 — 저장 못 하는 것과 못 쓰는 것은 다르다.
- 아직 아닌 것: **이 저장은 이 PC의 이 브라우저 안에만 있다.** 다른 기기·팀원 공유는 서버(DB) 저장이 필요하고 그건 다음 단계다. 화면은 `formStore` 의 함수만 보므로, 서버 저장은 그 안쪽을 바꾸는 것으로 얹힌다.
- 검증 못 한 것: **IndexedDB 는 node:test 환경에 없어 자동 테스트가 없다.** 저장·재접속·삭제는 브라우저에서 눈으로 확인해야 한다. 이 부분이 회귀 방지 사각지대라는 걸 기록해 둔다.

## 2026-09-10 · 만들기 · 서류함 모양 목록 — 분류 탭·즐겨찾기·최근 사용·검색

- 무엇을 만들었나: 저장된 양식을 사내 그룹웨어의 서식함처럼 **서류 카드**로 늘어놓는다. 분류 탭, 카드 모서리의 즐겨찾기 별, 최근 사용순 정렬, 검색. `apps/web/src/features/forms/FormGallery.tsx`.
- **분류는 코드에 박지 않고 사용자가 만든다.** 참고로 받은 화면에는 `제안 / 신청·청구` 아래 `공사사유·기술검토·대외공문 발송…` 같은 분류가 있었는데, 그건 **그 회사의 서류 체계**다. 코드에 적어 넣으면 분류 하나 늘릴 때마다 개발자를 불러야 한다. 탭은 **실제로 쓰이고 있는 분류에서 만들어** 빈 탭이 남지 않게 했다.
- **"미분류"는 항상 맨 끝 탭이다.** 정리되지 않은 것이 앞에 오면 목록이 지저분해 보이고, 정리할 동기도 줄어든다.
- **즐겨찾기(별)를 눌러도 `updatedAt` 은 밀지 않는다.** 별을 누른 건 서류 내용을 고친 게 아니다. 여기서 시각을 밀면 "최근 수정" 정렬이 사실과 달라진다. "최근 사용"은 따로 `openedAt` 을 둬서 **열어 보기만 해도** 갱신되게 했다 — 이 둘은 다른 질문이라 한 필드로 겸할 수 없다.
- **뒤늦게 생긴 항목은 읽는 길목 한 곳에서 채운다.** 분류·즐겨찾기는 저장 기능보다 나중에 생겨서 그 전에 올린 양식에는 없다. 읽는 쪽마다 `?? 기본값`을 흩뿌리는 대신 `normalize()` 하나를 통과하게 했다 — **저장소에서 나온 값은 전부 모양이 같다**는 보장이 생긴다.
- **읽기-고치기-쓰기를 `patchForm()` 하나로 모았다.** 값 저장·분류 변경·즐겨찾기·최근 사용이 전부 같은 모양(한 트랜잭션 안에서 get→put)이라, 따로 쓰면 그중 하나만 트랜잭션을 나눠 다른 탭의 원본을 덮어쓰는 사고가 난다.
- 아직 아닌 것: 분류의 2단계 구조(참고 화면의 `제안 / 신청·청구` 탭). 지금은 1단계다. **분류가 실제로 몇 개까지 늘어나는지 보고 정한다** — 쓰이지 않을 계층을 미리 만들면 올릴 때마다 고르는 칸만 늘어난다.

## 2026-09-10 · 고치기 · 넓은 양식이 잘리는 문제 — "가로 맞춤" 배율

- 증상: 21열짜리 대장 양식(`QA-7.3-2`, 49행 × 21열, 병합 139곳)을 열면 오른쪽이 잘려 보였다. 가로 스크롤은 있었지만, **"스크롤하면 보인다"는 "잘렸다"로 읽힌다** — 종이 양식은 한눈에 보이는 게 기본이라서.
- 고친 방법: 배율에 **"가로 맞춤"**을 넣고 기본값으로 삼았다. 남은 폭 ÷ 표 전체 폭으로 계산하되 **줄이기만 한다** — 좁은 양식을 억지로 늘리면 글자가 뭉개진다.

- 남은 폭도 `ResizeObserver` 로 따라간다. 창 크기·사이드바에 따라 바뀌므로 첫 렌더 때 한 번 잰 값으로는 틀린다.

- 페이지 폭도 `max-w-6xl`(1152px) → 1600px 로 넓혔다. 상자가 좁으면 "가로 맞춤"이 그만큼 더 줄여 글자가 작아진다.

- **그림에 `pointer-events: none` 을 준다.** 안 그러면 그림에 가린 칸을 눌러 고칠 수 없다. 양식은 그림 위에도 글을 적는 자리가 있다.
- **배율은 표와 그림을 함께 담은 상자에 건다.** 따로 걸면 그림 자리가 표와 어긋난다.

## 2026-09-10 · 고치기 · "로고가 여전히 안 보인다" — 조용한 실패 세 곳을 막았다

- 상황: 파서는 그림을 제대로 꺼내는데(테스트 통과) 화면에는 안 나온다는 보고. **원인을 특정하지 못한 채 다음 기능으로 넘어가면, 도형 그리기도 같은 자리에서 똑같이 안 보인다** — 화면에 얹는 경로가 같기 때문이다. 그래서 먼저 "왜 안 보이는지 알 수 있게" 만들었다.

  2. **`new Uint8Array(모르는 값)` 은 길이 0 을 조용히 만든다.** exceljs 가 주는 바이트 모양이 환경마다 다르다(Node=Buffer, 브라우저 번들=폴리필/Uint8Array, 직렬화 후=`{type:'Buffer',data:[…]}`). Node 테스트는 통과하는데 브라우저만 깨지는 전형적인 자리다. → 모양별로 나눠 변환하고, 못 알아보면 `null` 을 돌려 **실패를 실패로** 만든다.
  3. **저장본 다시 읽기 실패를 `catch {}` 로 삼키고 있었다.** 새 파서로 못 읽으면 옛 결과로 조용히 열려서, 사용자에게는 "새 기능이 안 되는 것"으로만 보인다. → 사유를 `upgradeError` 로 들려 보내 화면에 띄운다.
- 함께 고친 것: `saveForm` 이 원본 바이트를 **복사해서** 담는다. 파싱에 넘긴 그 버퍼를 그대로 저장하면, 라이브러리가 소유·이관해 비워 버렸을 때 "원본이 빈" 양식이 저장되고 이후 어떤 파서 개선도 반영되지 않는다.
- 교훈: **기능이 실패했을 때 사용자 화면이 "정상"과 구분되지 않으면, 그건 버그가 아니라 설계 결함이다.** 이번엔 세 군데가 전부 그 모양이었다.

- **인쇄 영역이 곧 양식이다.** 업무 양식에는 인쇄 영역 밖에 메모·계산용 도형이나 다 쓴 껍데기 줄이 남아 있는 일이 흔하다. 이 시트는 내용 범위가 49행×21열인데 인쇄 영역은 `A1:N29` 였고, 잘라내니 **도형 4개 + 번호만 남은 껍데기 줄 20개**가 함께 사라졌다. "인쇄했을 때 나오는 것"이 사용자가 생각하는 양식이다.
- **끝만 자르고 시작점은 건드리지 않는다.** 시작을 옮기면 행·열 번호가 밀리는데, 사용자가 적어 둔 글자는 셀 좌표(`행:열`)에 붙어 있어서 **이미 작성한 내용이 엉뚱한 칸으로 간다**. 실제 양식은 거의 A1 에서 시작하므로 잃는 것이 거의 없다.
- `worksheet.pageSetup.printArea` 로 읽는다(exceljs 가 준다 — 직접 파싱할 필요 없었다). 여러 조각(`A1:N29,P1:R9`)일 수 있어 전부 감싸는 크기로 잡는다.
- **잘라냈다는 사실을 화면에 적는다.** 시트 정보줄에 "인쇄 영역 A1:N29까지만 표시". 원본에 있던 20줄이 말없이 사라지면 사용자는 데이터가 없어졌다고 본다. **잘라내지 않았을 때는 표시하지 않는다** — 안 잘렸는데 안내가 뜨면 그것도 헷갈린다(테스트로 박았다).
- 도형·그림도 함께 걸러낸다. 표를 자르면 밖의 것들은 좌표가 표 오른쪽·아래로 넘어가므로, **시작점이 표 안에 있는 것만** 남긴다. 걸쳐 있는 것은 원본에서도 걸쳐 있으므로 남긴다.
- `PARSER_VERSION` 5 → 6.

## 2026-09-10 · 고치기 · 워터마크 — 회전·투명도·점선·밝기 보정

- 증상: `견본` 시트의 "Sample" 워터마크가 **글자 없는 진한 붉은 덩어리**로 나와 표를 가렸다. 원본은 비스듬히 누운 연분홍 반투명 상자에 점선 테두리, 진한 붉은 글자다.
- 네 가지를 한꺼번에 놓치고 있었다. 하나만 고쳐서는 원본이 되지 않는다:
  1. **밝기 보정(`lumMod`/`lumOff`)** — 배경은 기준색 `C0504D` 에 20%+80% 보정이 걸린 연분홍인데, 보정을 무시해 기준색 그대로 칠했다. **글자색도 같은 기준색이라 배경과 색이 같아져 글자가 통째로 사라졌다.** "글자가 안 나온다"의 원인이 색 계산이었다.
  2. **투명도(`alpha`)** — 75%. 워터마크는 표가 비쳐 보여야 워터마크다.
  3. **회전(`rot`)** — 60000분의 1도 단위. `20503159` = 341.7° = 화면에서 -18.28°.
  4. **점선(`prstDash`)** — `sysDash`.
- **밝기 보정은 HSL 의 L 에만 건다**: `L' = L × lumMod + lumOff`. 전에는 검정 계열만 특별 취급하는 임시 코드였는데, 일반식으로 바꾸니 기존 연결선(#404040)도 같은 식으로 나온다 — 특례가 사라졌다.
- **보정값은 그 색 요소 안쪽에서만 찾는다.** 조각 전체를 훑으면 옆에 있는 다른 색의 보정을 끌어다 쓴다(글자 서식 안에는 윤곽선 색과 채움 색이 함께 들어 있다). 이걸 놓치면 색이 조용히 틀린다.
- 회전은 **도형 가운데를 축**으로 건다. 엑셀도 같은 기준이라 자리가 어긋나지 않는다. SVG 는 `rotate(deg cx cy)`, HTML 은 `transform: rotate()` 로 기준을 맞췄다.
- 회귀 방지: 워터마크 값 검증에 더해 **"회전·점선이 없는 도형에는 값을 붙이지 않는다"** 를 넣었다. 기본값을 잘못 채우면 멀쩡한 순서도가 전부 기울어진다.
- `PARSER_VERSION` 6 → 7.

## 2026-09-10 · 만들기 · 그룹으로 묶인 도형을 푼다 (샘플 3번째 파일)

- 새 샘플(`101. 이해관계자니즈와기대2.xlsx`, 시트 6개)로 검증하면서 나온 것들.
- **찾은 버그 — 그룹(`grpSp`)으로 묶인 도형이 통째로 빠졌다.** 순서도의 첫 상자가 글자 없는 빈 네모로 나왔다. 엑셀에서 도형을 묶으면 안쪽 좌표가 **그룹만의 좌표계**로 바뀐다 — `chOff`(원점)/`chExt`(크기)가 그 좌표계이고, 화면에서 그룹이 차지하는 자리는 앵커가 정한다. **둘 사이를 비례로 옮겨야** 제자리에 온다. 그냥 안쪽 좌표를 쓰면 도형이 엉뚱한 곳으로 튄다.
  - 그룹 안에 또 그룹이 있을 수 있어 재귀로 푼다. 안쪽 그룹을 먼저 떼어 내고 남은 것에서 도형을 찾는다 — 안 그러면 같은 도형을 두 번 담는다.
  - 푼 뒤에는 기존 "장식용 테두리 합치기" 규칙이 그대로 걸려, 문서 기호 + 글자 상자가 하나로 합쳐졌다. **규칙을 일반형으로 만들어 둔 것이 새 파일에서 값을 했다.**
- **EMF/WMF 그림은 명시적으로 건너뛴다.** 이 파일에 4개 있었는데, 마침 시트 밖(30~47행)에 있어 인쇄 영역 규칙에 걸려 이미 빠지고 있었다 — **우연이었다.** 브라우저는 EMF 를 못 열어 넣어도 깨진 그림이 되고, `alt` 가 비어 있어 화면에서는 아무것도 없는 것처럼 보인다. 우연에 기대지 않도록 형식을 보고 거른다.
