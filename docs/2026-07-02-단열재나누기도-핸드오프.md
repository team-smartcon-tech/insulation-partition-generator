## 3. 실행 방법

```bash
# 사전: Node 20+, pnpm 10.x (corepack 권장)
pnpm install                 # 저장소 루트에서 (워크스페이스 전체)
pnpm --filter web dev        # 개발 서버 → http://localhost:5173
#   ※ 5173이 다른 앱에 점유돼 있으면 Vite가 자동으로 5174 등 다음 포트를 사용(콘솔 URL 확인)
pnpm --filter web build      # 프로덕션 빌드(타입체크 포함)
pnpm --filter web typecheck  # 타입 검사만
```

화면에서: DXF 업로드 → 외벽 트레이싱 → 나누기도 미리보기 → 매트릭스/산출서 → 내보내기. **저장/불러오기 버튼은 없음(Phase 3)**.

## 5. 남은 작업 — Phase 3 (저장/불러오기)

원본에서 떼어낸 저장 기능을 **새 서버 + 새 DB**로 재구성한다. 세부는 이관 계획서 §2~§4 참조.

### 3-A. 코드 (완료 — 2026-07-02)
- `apps/worker/src/index.ts`: 저장 API 8개(Hono) 이식 완료 — `/api/elevation-projects*`
  - `GET/POST /api/elevation-projects`, `GET/PATCH/DELETE /:projectId`, `GET·DELETE /:projectId/revisions/:revId`, `POST /:projectId/revisions`(multipart)
  - 테이블명은 접두사 없이 `elev_projects`/`elev_revisions`, 버킷은 `ELEV_DXF_BUCKET` env(기본 `elev-dxf`)
  - 접근 제어 없음(§6-1 추천안 기준). 도입 시 라우트 앞단 미들웨어로 추가
- `packages/shared/src/index.ts`: `ElevState`/`ElevSummary`/`ElevTypeMatrix`/`DbElev*` 공용 타입 이동(web `types.ts`는 재수출)
- `apps/web`: `features/elevation/api.ts`(DCR 인증 제거한 클라이언트) + `hooks.ts`(react-query) 신규, `main.tsx`에 `QueryClientProvider`, 페이지에 프로젝트/REV 바·REV 목록 패널·`buildElevState`/`applyElevState`(레거시 마이그레이션 포함) 복원
- `apps/web/vite.config.ts`: `/api` → 로컬 wrangler(8787) 프록시 (`IPG_API_TARGET`으로 덮어쓰기 가능)
- `supabase/migrations/20260702000001_elev_projects.sql`: 새 DB용 마이그레이션 작성(아직 미적용 — 3-B)
- **검증:** shared·worker·web typecheck 통과, web build 통과, `wrangler deploy --dry-run` 통과, 로컬 `wrangler dev`에서 `/health`·라우팅·입력 검증 응답 확인(시크릿 미등록이라 Supabase 호출은 3-B 이후 실검증)

## 7. 안전·운영 규칙 (필수)

- 원본 SSX 저장소는 **읽기 전용**. 수정 금지.
- 비밀값(Supabase 키/JWT)은 코드·문서·`.env` 커밋 금지 → Cloudflare Secrets 관리. 프론트엔드에 서버 비밀값 노출 금지.
- 비공개 Storage 파일은 서명 URL(signed URL)로만 임시 발급. 인증 없이 URL 직접 발급 금지.
- 브랜치 전략: `feature/{닉네임}` → PR → `main` → (승격) → `deploy`. **`main` 직접 push 금지**(로컬 훅으로 차단됨).
- 커밋/푸시/배포/운영 DB 변경/삭제성 마이그레이션은 사용자 승인 후에만.
- GitHub 저장소는 **`team-smartcon-tech` 조직**에 둔다(개인 레포 금지).
