# 임원 브리핑 덱

**비개발자 임원에게 이 템플릿을 소개하는 9장짜리 발표 자료다.** 배경 → 해결 방식 → 구성 요소 → 작동 방식 → 리스크 관리 → 도입 절차 → 운영 현황 → 정리 순서로, 장 제목이 그 장의 주장을 담고 부제가 근거를 받는다.

- 기준 표준 버전: `2.16-draft`
- 최종 수정일: 2026-08-31

---

## 파일 구성

| 파일 | 무엇인가 |
|---|---|
| `woomi-agent-template-exec-brief.pptx` | **발표용 PowerPoint.** 16:9(13.33×7.5in), 9장. 이걸 열어서 발표한다 |
| `*.dc.html` (9개) | 슬라이드 원본. 장별로 한 파일이며 파일명이 곧 슬라이드 이름이다 |
| `canvas.json` | 슬라이드 배치(3×3)와 인쇄 설정 |
| `build-pptx.mjs` | `.pptx` 생성기. 원본과 좌표를 `1px = 1/96in` 으로 맞춰 옮긴다 |

슬라이드 순서는 `Main`(표지) → `Problem` → `Solution` → `Components` → `HowItWorks` → `Safety` → `Adoption` → `Maturity` → `Summary` 다.

---

## 발표 전에 채울 것

대괄호로 표시된 다섯 자리는 **실제 값을 모르는 채로 둔 것**이다. 발표 전에 채운다.

| 위치 | 자리 |
|---|---|
| 표지(`Main`) | `[발표자 · 소속]`, `[발표일]` |
| 정리(`Summary`) | `[검토 요청 1~3]` — 예시 문구가 들어 있으니 실제 요청 사항으로 바꾼다 |

pptx에서 직접 고치는 것이 가장 빠르다. 원본까지 함께 맞추려면 아래 순서를 따른다.

---

## 고칠 때

문구만 바꾸는 정도면 **pptx에서 직접 고치고 끝낸다.** 다만 원본(`.dc.html`)과 어긋나므로, 다음에 원본에서 다시 생성하면 그 수정은 사라진다. 계속 쓸 자료라면 원본을 고치는 쪽이 맞다.

### 원본을 고치고 pptx를 다시 만들기

`.dc.html`은 그냥 HTML이다. 텍스트와 인라인 스타일을 고치면 된다. 그다음 같은 내용을 `build-pptx.mjs`에도 반영하고 다시 생성한다.

```bash
npm install pptxgenjs        # 이 저장소 의존성이 아니다. 생성할 때만 한 번 설치한다
node docs/exec-brief/build-pptx.mjs docs/exec-brief/woomi-agent-template-exec-brief.pptx
```

> `pptxgenjs`를 루트 `package.json`에 넣지 않은 이유: 이 템플릿을 복사하는 모든 프로젝트가 발표 자료 생성용 의존성을 끌고 가게 된다. 문서 전용 도구는 필요할 때만 설치한다.

### 화면에서 보면서 고치기

9장을 한 화면에 펼쳐 놓고 클릭해 고칠 수 있는 캔버스가 따로 게시되어 있다.

- <https://claude.ai/code/artifact/67df09b2-6a1a-4e66-98c3-216a0195a257>

이 캔버스는 `.dc.html` 9개와 `canvas.json`을 묶어 만든 것이고, 조립 결과물(약 2.5MB)은 이 저장소에 담지 않았다. 원본이 여기 있으므로 언제든 다시 만들 수 있다.

## 디자인 기준

`apps/web/app/app.css`의 실제 토큰을 그대로 썼다. 새로 만든 색은 없다.

| 쓰임 | 값 |
|---|---|
| 강조 | `#4f46e5` (표지·정리 장의 어두운 배경에서는 같은 계열의 밝은 단계 `#a5b4fc`) |
| 본문 / 보조 본문 | `#0f172a` / `#64748b` |
| 배경 / 면 / 선 | `#ffffff` · `#f1f5f9` / `#eef2ff` / `#e2e8f0` |
| 되는 것 / 안 되는 것 | `#059669` / `#b45309` |
| 모서리 | 8px 이하 |

`.agents/ui/DESIGN.md`의 방향(장식보다 정보 밀도, 장식용 gradient 금지)을 따른다. 한글 가독성 때문에 본문 서체만 다르다 — 캔버스는 Noto Sans KR, pptx는 Windows에 기본으로 있는 맑은 고딕이다.

## 검증하지 못한 것

- **pptx 렌더 검수를 실행하지 못했다.** 작업 환경에 LibreOffice와 `pdftoppm`이 없어 슬라이드를 이미지로 뽑아 눈으로 확인하지 못했다. 스키마 검증(`validate.py`)과 텍스트 추출 검사는 통과했다. **처음 열 때 9장을 넘겨 보며 글자가 상자 밖으로 넘치지 않는지 확인한다.**
- 슬라이드는 고정 크기다. 문구를 크게 늘리면 아래가 잘릴 수 있다. 현재 장당 40~140px 여유를 두었다.
