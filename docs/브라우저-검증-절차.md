# 브라우저 검증 절차 (크롬 DevTools)

> 작성 2026-09-13 / 최종 수정 2026-09-14 / 상태: 표준
>
> **기능·메뉴·탭 단위 개발은 PR 전에 이 절차로 브라우저에서 검증한다.**
>
> 파생 프로젝트(Smart Planner)에서 쓰던 절차를 템플릿 표준으로 들여온 것이다. 파일명에 날짜를 넣지 않는다 — 특정 시점의 기록이 아니라 **계속 쓰는 기준**이다.

> **이 저장소 주의(insulation-partition-generator)**: 2026-10-21 템플릿 2.27-draft 적용 때 들여왔다. 절차(크롬 CDP·확인 항목·뒷정리·PR 기록)는 그대로 쓰고, 아래 차이를 먼저 본다.
> - **CI 가 없다.** 본문의 `pr-checks.yml`(이 저장소에는 없음)과 `format:check`·`lint`·`test` 다섯 검사는 템플릿 기준이다. 이 저장소에서 자동 검사로 돌리는 것은 `AGENTS.md` 11장 "검증 명령(실제값)"이다.
> - **개발 서버**: `pnpm dev` 가 worker(`wrangler dev --port 9887`)와 web(Vite **5473**)을 함께 띄운다. 접속은 `http://localhost:5473`(Vite 시작 로그의 주소를 그대로 쓴다), `/api/*` 는 Vite 가 `127.0.0.1:9887` 로 프록시한다(`apps/web/vite.config.ts`). 본문의 5173 은 템플릿 값이다.
> - **로그인**: 데모 계정이 없다. DCR 통합로그인(실제 계정, 이메일+비밀번호)이고, 로컬은 `apps/worker/.dev.vars` 에 `IPG_JWT_SECRET`·`COOKIE_SECURE=false` 가 있어야 세션이 붙는다(`CLAUDE.md` 0장). 비밀번호를 스크립트·로그·보고에 남기지 않는다.
> - 본문의 React Router(`createCookieSessionStorage` 등) 예시와 `admin@woomi.dev` 계정은 **템플릿 스캐폴드 기준**이다. 이 저장소의 세션은 Worker 가 발급하는 HttpOnly `ipg_session` 쿠키다.
> - 저장 확인은 Supabase(전용 `yzercziwazfrjsjnmbhr`) — 운영 DB 이므로 조회만 하고, 검증용으로 만든 데이터는 화면에서 지운다.

## 왜 하는가

`pnpm format:check`·`typecheck`·`lint`·`test`·`build` 는 **"화면에서 실제로 눌러 보면 되는가"를 증명하지 않는다.** 다섯을 다 통과하고도 화면에서 안 되는 것을 파생 프로젝트에서 실제로 겪었다:

- 점(하루) 마일스톤 바를 가운데에서 끌면 이동이 아니라 **기간이 생겼다.** 바 폭 10px 중 오른쪽 크기조절 핸들이 6px 이라 이동 영역이 4px 뿐이었다. **테스트 490건이 전부 통과하는 상태였고**, 브라우저에서 끌어 보고서야 드러났다.

그리고 템플릿 저장소의 CI(`.github/workflows/pr-checks.yml` (이 저장소에는 없음))는 **검사만 하고 배포하지 않는다.** PR 브랜치가 어디에도 뜨지 않으므로 "개발 서버에서 확인" 이라는 선택지가 없다. 로컬 브라우저 검증을 건너뛰면 확인할 자리 자체가 없다.

## 언제 하는가

| 변경 | 브라우저 검증 |
| --- | --- |
| 메뉴·탭·화면의 **기능** 추가·변경 (저장, 편집, 드래그, 업로드, 모드 전환 등) | **필수** |
| 문구·색·여백만 바꾸는 수정, 문서, 리팩터 | 불필요 |
| 서버·계산 로직만 바꾸고 화면 동작이 그대로인 경우 | 단위 테스트로 충분 |

## 준비물

### 1. 크롬 DevTools — 설치할 것이 없다

**"DevTools 를 설치한다"는 말은 오해다.** DevTools 는 크롬·엣지에 **내장**되어 있다(`F12`). 따로 받을 것이 없다.

이 절차가 쓰는 것은 DevTools **프로토콜(CDP)** 이다 — 크롬을 `--remote-debugging-port` 로 띄우면 프로그램이 클릭·입력·스크린샷을 대신할 수 있다. **Playwright·Puppeteer 같은 패키지도 깔지 않는다.** Node 내장 `WebSocket` 으로 직접 붙는다.

### 2. 크롬(또는 엣지)이 있는지 확인한다

```powershell
# Windows
Test-Path "$env:ProgramFiles\Google\Chrome\Application\chrome.exe"
Test-Path "${env:ProgramFiles(x86)}\Microsoft\Edge\Application\msedge.exe"   # 대체 가능
```

```bash
# macOS / Linux
ls "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" 2>/dev/null \
  || command -v google-chrome chromium 2>/dev/null
```

**둘 다 없으면 에이전트가 임의로 설치하지 않는다.** 먼저 사용자에게 아래를 그대로 설명하고 승인을 받는다.

> **크롬이 필요한 이유**: 이 검증은 "화면이 그려지는가"가 아니라 **"눌렀을 때 실제로 동작하고 저장되는가"** 를 봅니다. 그러려면 실제 브라우저 엔진에서 자바스크립트가 돌고, 클릭·드래그·키 입력이 사람이 하는 것과 같은 이벤트로 들어가야 합니다. 크롬은 `--remote-debugging-port` 로 띄우면 프로그램이 이 조작을 대신할 수 있고, 콘솔 오류와 실패한 네트워크 응답까지 함께 수집됩니다. 별도 도구를 설치하지 않고 이미 쓰는 브라우저를 그대로 씁니다.

승인받았을 때의 설치 경로:

| OS | 방법 |
| --- | --- |
| Windows | `winget install Google.Chrome` — 또는 <https://www.google.com/chrome/> |
| macOS | `brew install --cask google-chrome` — 또는 위 주소 |
| Linux (Debian/Ubuntu) | 배포판 저장소의 `chromium`, 또는 Google 공식 `.deb` |

**엣지가 이미 있으면 그걸 쓴다.** 같은 CDP 를 쓰므로 아래 절차가 그대로 동작한다 — `chrome.exe` 자리에 `msedge.exe` 를 넣으면 된다. **크롬이 없다는 이유로 새로 설치하기 전에 엣지부터 확인한다.**

### 3. Claude in Chrome — 있으면 더 쉽다. 없어도 된다

Anthropic 의 **Claude for Chrome** 확장을 쓰면 아래 4·5단계(CDP 로 조작)를 Claude 가 브라우저에서 직접 한다. 원격 디버깅 포트를 띄우지 않아도 되고, 화면을 보면서 대화로 시킬 수 있다.

**있는지 확인**: 크롬 주소창에 `chrome://extensions` → 목록에 Claude 가 있는지, 툴바에 아이콘이 보이는지.

**없으면**: Anthropic 공식 안내 <https://claude.ai/chrome> 를 따른다. **제공 범위가 요금제·지역에 따라 제한될 수 있으므로** 설치를 지시하기 전에 사용자에게 먼저 확인한다. 확장 설치는 브라우저 권한을 주는 일이라 **에이전트가 대신 설치하지 않는다.**

> **없어도 이 문서의 절차는 그대로 동작한다.** Claude in Chrome 은 편의 수단이지 요구사항이 아니다. 아래 4·5단계가 확장 없이 도는 기본 경로다.
>
> **주의**: 확장으로 브라우저를 조작할 때는 **로그인된 개인 프로필**이 그대로 노출된다. 검증에는 아래처럼 **별도 임시 프로필**을 쓰는 편이 안전하다.

## 절차

### 1. 개발 서버를 띄운다

```bash
pnpm dev          # http://127.0.0.1:5173
```

`localhost` 대신 **`127.0.0.1`** 로 접속한다. 쿠키를 넣을 호스트와 접속 호스트가 다르면 세션이 붙지 않는다.

**다만 서버가 실제로 그 주소에 바인딩됐는지 먼저 본다.** Vite 는 기본적으로 `localhost` 에만 붙어서, 그대로 `127.0.0.1` 로 가면 `ERR_CONNECTION_REFUSED` 가 난다(실제로 겪었다). 시작 로그가 찍은 주소를 그대로 쓰거나, `pnpm dev --host 127.0.0.1` 로 띄운다. **포트도 확인한다** — 5173 이 이미 쓰이고 있으면 Vite 가 조용히 5174 로 올라간다.

### 2. 크롬을 원격 디버깅으로 띄운다

```bash
chrome.exe --headless=new --disable-gpu --disable-extensions \
  --remote-debugging-port=9222 \
  --user-data-dir="<저장소 밖 임시 경로>" \
  --no-first-run --no-default-browser-check --window-size=1600,1200 about:blank
```

**프로필 경로를 저장소 안에 두지 마라.** Vite 가 크롬 프로필의 파일 변경을 감지해 페이지를 계속 새로고침하고, 그러면 하이드레이션이 끊겨 **모든 클릭이 먹지 않는다.** 실제로 겪은 함정이다.

### 3. 로그인한다 — 이 스캐폴드는 데모 계정이 있다

`/login` 에서 아래 계정으로 **그냥 폼에 입력하면 된다**(`app/features/auth/model/credentials.server.ts`).

| 이메일 | 비밀번호 | 역할 |
| --- | --- | --- |
| `admin@woomi.dev` | `admin1234` | 관리자 |
| `manager@woomi.dev` | `manager1234` | 매니저 |
| `member@woomi.dev` | `member1234` | 구성원 |

**역할별로 보이는 메뉴가 다르므로**, 권한 분기를 건드렸으면 세 계정 모두로 확인한다.

<details>
<summary>프로젝트가 실제 인증을 붙인 뒤 — 쿠키를 직접 만드는 방법</summary>

데모 계정을 없애고 실제 인증을 붙였다면, 로그인 화면을 거치지 않고 세션 쿠키를 만들 수 있다. **개발 빌드에서만** 통한다 — `SESSION_SECRET` 이 없을 때 쓰는 폴백 키(`app/features/auth/model/session.server.ts`)에 의존하기 때문이다. 운영 빌드는 시크릿을 반드시 설정하므로 이 방법이 통하지 않으며, **통해서도 안 된다.**

```js
import { createCookieSessionStorage } from "react-router"
const storage = createCookieSessionStorage({
  cookie: { name: "woomi_session", httpOnly: true, path: "/", sameSite: "lax",
            secrets: ["dev-insecure-session-secret-change-me"], secure: false },
})
const s = await storage.getSession()
s.set("userId", "<사용자 id>")
console.log((await storage.commitSession(s)).split(";")[0])
```

만든 쿠키는 CDP `Network.setCookie` 로 넣되 **`url` 을 접속 주소와 같게** 준다.

</details>

### 4. 조작하고 확인한다

- `Page.navigate` 후 **하이드레이션을 기다린다** — `typeof window.__reactRouterContext === "object"` 가 될 때까지. Vite 는 HMR 연결 때문에 `readyState` 가 `complete` 로 가지 않으므로 `load` 이벤트를 기다리면 영원히 멈춘다. **하이드레이션 전에 클릭하면 아무 일도 일어나지 않는다.**
- 클릭은 `el.click()` 로 충분하다. **드래그·더블클릭은 `Input.dispatchMouseEvent`** 로 보낸다. 더블클릭은 `clickCount` 1 → 2 로 **누르고 떼기를 두 번** 해야 한다.
- 텍스트 입력은 `Input.insertText` + `Input.dispatchKeyEvent`(Enter). 값만 바꾸고 `blur()` 를 부르면 **포커스가 없어 커밋되지 않는다.**
- 파일 업로드는 `DOM.setFileInputFiles` 로 숨은 `input[type=file]` 에 넣는다.
- `Runtime.exceptionThrown`·`console.error`·**4xx/5xx 응답**을 함께 모아 **"오류가 없다"까지** 확인한다.
- `Page.captureScreenshot` 으로 화면을 남긴다.

### 5. 저장되었는지 확인한다

화면 표시만 보지 마라. **화면은 낙관 갱신으로 성공처럼 보일 수 있다.**

- **이 스캐폴드는 인메모리 목업이다**(`app/entities/*/model/*.mock.ts`). 서버를 재시작하면 사라지므로, "새로고침 후에도 남아 있는가" 까지가 확인 범위다.
- **프로젝트가 DB 를 붙였으면 거기서 본다.** 화면이 아니라 저장소를 조회해 실제 행을 확인한다.

### 6. 뒷정리 — 빠뜨리지 마라

- 검증에 만든 데이터(행·첨부·**스토리지 객체**)를 지운다. 스토리지는 메타만 지우면 고아 객체가 남는다.
- 임시 스크립트·스크린샷·크롬 프로필을 지운다. `*.tmp.*` 로 이름 지어 두면 한 번에 지운다.
- 개발 서버와 크롬을 종료한다.

### 7. PR 에 결과를 적는다

무엇을 눌러 보았고, 무엇이 저장됐고, **무엇을 확인하지 못했는지** 적는다. **"확인하지 못한 것"을 빼면 검증이 아니라 홍보다.**

## 자주 밟는 함정 (전부 실제로 겪음)

| 증상 | 원인 |
| --- | --- |
| 클릭이 아무 반응 없다 | 하이드레이션 전에 눌렀다 |
| 화면이 계속 새로고침되고 스크립트가 안 붙는다 | 크롬 프로필을 저장소 안에 뒀다 (Vite 가 감시) |
| 로그인이 안 붙는다 | 쿠키를 `localhost` 로 넣고 `127.0.0.1` 로 접속했다 |
| `Page.loadEventFired` 를 영원히 기다린다 | Vite HMR 연결로 `load` 가 안 끝난다 — 화면 문구로 판정한다 |
| 더블클릭이 안 열린다 | `clickCount:2` 한 번만 보냈다 (두 번 눌렀다 떼야 한다) |
| 입력값이 저장되지 않는다 | 포커스 없이 `blur()` 를 불렀다 — 실제 키 입력으로 바꾼다 |
| 크롬이 없다며 설치부터 하려 한다 | **엣지를 먼저 확인한다.** 같은 CDP 로 그대로 동작한다 |
| `ERR_CONNECTION_REFUSED` | Vite 가 `localhost` 에만 바인딩됐는데 `127.0.0.1` 로 갔다. 포트도 확인한다(5173 이 쓰이면 5174 로 올라간다) |
