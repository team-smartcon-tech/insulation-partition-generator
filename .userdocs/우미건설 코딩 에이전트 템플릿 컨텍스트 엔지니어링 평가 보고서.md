# 우미건설 코딩 에이전트 템플릿 컨텍스트 엔지니어링 평가 보고서

## TL;DR
- Anthropic의 2026년 7월 24일 "Claude 5 세대 컨텍스트 엔지니어링 새 규칙"(Thariq Shihipar 작성)의 핵심은 **"뺄셈"**이다: 강한 모델은 규칙을 줄이고 판단에 맡길 때 더 잘 작동하며, Anthropic은 Claude Opus 5·Fable 5용으로 Claude Code 시스템 프롬프트의 80% 이상(보도 기준 약 800토큰 → 164토큰, 요청당 약 636토큰 확보)을 삭제하고도 "코딩 평가에서 측정 가능한 손실이 없었다(no measurable loss on our coding evaluations)".
- 우미 템플릿(v2.3-draft)은 AGENTS.md 단일 소스 지향, 사전 구성된 안전 훅 등 좋은 뼈대를 갖췄으나, 블로그 기준으로 볼 때 "AGENTS.md에 모든 것을 넣는" 구식 패턴(프로그레시브 디스클로저 부재, 스킬 미분리, 멀티 하네스 중복)에 취약할 가능성이 높다.
- 우선순위 개선 Top 3: **①AGENTS.md 경량화 + 스킬 트리 분리, ②멀티 하네스 지침 중복 제거(단일 소스 + 참조), ③검증 루프를 스킬로 분리** — 세 가지 모두 비개발자도 `/doctor` 명령과 파일 편집만으로 실행 가능하다.

> **중요한 한계:** 평가 시점(2026-07-30)에 `team-smartcon-tech/woomi-coding-agent-template` 레포는 git clone, GitHub REST API, raw 파일 접근, 웹 검색(정확 일치 검색 포함) 등 **모든 공개 방법으로 접근되지 않았다**(비공개 또는 미인덱싱으로 추정). 따라서 본 보고서의 레포 관련 평가는 사용자가 제공한 구조 설명(AGENTS.md 주 지침, React Router v7 + Hono/Cloudflare Worker + Supabase, pnpm 모노레포, Claude Code/Codex/Copilot 멀티 하네스, `.claude/settings.json` 및 `.githooks/` 안전 훅)에 근거한 **"구조 기반 추정 평가"**이며, 실제 파일 내용을 인용하지 못했다. 각 추정 항목에는 **[확정 검증 필요]**를 표시했고, 실제 파일 확정 검증은 아래 권고안의 `/doctor` 셀프 진단 절차로 대체·보완할 수 있다.

## Key Findings

### 블로그가 제시한 Claude 5 세대 컨텍스트 엔지니어링 원칙 전체 정리
Anthropic 기술스태프 Thariq Shihipar가 작성한 이 글은 "과거의 베스트 프랙티스가 이제는 미신(myth)이 되었다"고 선언하며, 이 대규모 삭제를 **"unhobbling(족쇄 풀기)"**이라 부른다. 핵심은 6가지 전환이다.

1. **규칙 부여 → 판단 위임 (Then: Give rules / Now: Let Claude use judgement).** 과거에는 "In code: default to writing no comments... Never write multi-paragraph docstrings" 같은 강한 규칙을 넣었지만, 이는 일부 상황(사용자 선호, 복잡한 코드의 다중 주석 필요)에서 틀린 지침이 된다. 새 모델은 판단력이 좋으므로 "주변 코드처럼 작성하라(Write code that reads like the surrounding code: match its comment density, naming, and idiom)"처럼 맥락 기반 지침이 낫다.
2. **예시 제공 → 인터페이스 설계 (Then: Give examples / Now: Design interfaces).** 예시는 오히려 모델의 탐색 공간을 특정 영역으로 제약한다. 도구/스크립트/파일의 파라미터를 표현력 있게 설계하는 데 집중하라(예: Todo 도구의 status enum(pending/in_progress/completed)과 "하나만 in_progress" 규칙이 사용법을 암시).
3. **모든 것을 앞에 배치 → 프로그레시브 디스클로저 (Then: Put it all upfront / Now: Progressive disclosure).** 필요할 때 필요한 컨텍스트만 로드하라. Anthropic은 검증·코드리뷰를 별도 스킬로 분리했고, 도구도 'deferred loading'으로 ToolSearch 시에만 전체 정의를 로드한다. CLAUDE.md/Skill.md도 "언젠가 필요할 모든 것을 담는 중앙 저장소"로 만들지 말고 "적시에 로드되는 파일 트리(a tree of files that can be loaded at the right time)"로 구성하라.
4. **반복 → 간결한 도구 설명 (Then: Repeat yourself / Now: Simple tool descriptions).** 구세대 모델은 컨텍스트 끝의 지침을 더 잘 듣는 경향이 있어 시스템 프롬프트와 도구 설명에 지침을 중복시켰다. 이제 중복을 제거하고 도구 사용법은 도구 설명(tool description)에만 둔다.
5. **CLAUDE.md 수동 메모리 → 자동 메모리 (Then: Memory in CLAUDE.md / Now: Auto-memory).** 과거 `#` 핫키로 CLAUDE.md에 수동 저장하던 것을, 이제 Claude가 작업·사용자에 관련된 메모리를 자동 저장한다.
6. **단순 스펙 → 리치 레퍼런스 (Then: Simple specs / Now: Rich references).** 단순 마크다운 플랜 대신 HTML 아티팩트, 테스트 스위트, 다른 코드베이스의 함수, 루브릭(rubric) 같은 고충실도 레퍼런스를 활용하라. 루브릭은 검증 에이전트를 띄워 "좋은 API 설계란 무엇인가" 같은 취향을 검증하게 해준다.

**"컨텍스트 조립" 4계층 가이드:**
- **시스템 프롬프트:** 제품 컨텍스트에 강하게 묶임. Claude Code 사용자는 거의 수정할 일 없음("you will likely never modify this"). 자체 에이전트 하네스를 만든다면 여기에 시간을 많이 써라.
- **CLAUDE.md:** 가볍게 유지. 레포가 무엇을 위한 것인지 간단히 기술하고, 토큰 대부분은 코드베이스의 "gotcha(함정)"에 써라(예: 타입을 하나의 모놀리식 파일에만 둔다는 규칙). 파일시스템/레포만 봐도 알 수 있는 "뻔한 것(the obvious)"은 넣지 마라. 프로그레시브 디스클로저를 적극 사용(예: 검증 지침이 여러 개면 검증 스킬을 만들고 CLAUDE.md에서 참조).
- **스킬(Skills):** 필요할 때 정보를 찾게 해주는 가벼운 가이드로 생각하라. 과도하게 제약하지 말 것(매우 중요한 영역 제외). 긴 스킬은 여러 파일로 쪼개라. 스킬은 당신/팀/제품 고유의 의견·지식·베스트 프랙티스를 담을 때 가장 좋다.
- **레퍼런스:** `@` 멘션으로 파일 참조. 코드 형태의 레퍼런스를 선호(디자인 설명이나 스크린샷보다 HTML 목업이 더 나은 결과).

**추가 원칙 — 컨텍스트 오염 방지:** 글은 "leave documentation as appropriate"와 "DO NOT add comments"처럼 시스템 프롬프트·스킬·유저 요청이 서로 충돌하는 메시지를 실제 내부 로그에서 지적한다. 규칙이 충돌하면 Claude가 실제 작업 전에 어떤 지침을 따를지 판단하느라 추론 토큰을 낭비한다. 이는 독립 연구로도 뒷받침된다 — arXiv:2606.15828("Configuration Smells in AGENTS.md Files", Hélio Victor F. dos Santos 외 4인, 2026-06-14)은 인기 오픈소스 레포 100개를 분석해 **91개 파일에서 최소 1개의 구성 스멜**을 발견했고(Lint Leakage 62%, Context Bloat 42%, Skill Leakage 35%), "충돌하는 지침(Conflicting Instructions)"과 "init 화석화(Init Fossilization, /init 생성 후 커밋 1개만 있으면 해당)"를 대표적 안티패턴으로 명시한다. 같은 논문이 인용한 Anthropic 문서 원문: *"if two rules contradict each other, Claude may pick one arbitrarily. Review your CLAUDE.md files periodically to remove outdated or conflicting instructions."*

**실행 도구:** Claude Code에서 `/doctor`(claude doctor) 명령으로 스킬·CLAUDE.md를 자동으로 "적정 크기(rightsize)"할 수 있다.

### 스킬 관련 정량 기준 (Anthropic 공식 문서)
- **SKILL.md 본문은 500줄 이하로 유지**하고 초과 시 여러 파일로 분리한다(원문: *"Keep SKILL.md body under 500 lines for optimal performance; Split content into separate files when approaching this limit."*).
- **3계층 로딩:** Level 1 메타데이터(name·description)는 스킬당 약 100토큰으로 **상시 프리로드**(스킬 50개 설치 시 약 5,000토큰), Level 2 SKILL.md 본문은 트리거 시, Level 3 번들 파일은 참조 시에만 로드된다. name 필드 최대 64자, description 최대 1,024자. 따라서 "이 내용이 무관한 턴에 비용을 내기 싫다면" 그 내용은 CLAUDE.md가 아니라 스킬에 둬야 한다.
- **실무 권고(HumanLayer, DeployHQ 등):** AGENTS.md/CLAUDE.md는 대략 100~150줄 이내. 500줄을 넘으면 대부분 무시되며 Codex CLI는 `project_doc_max_bytes` 초과분을 조용히 잘라낸다. 멀티 툴 간 복붙 중복 금지, 단일 소스 + 참조. (참고로 Gloaguen 외 2026 연구는 개발자가 직접 작성한 AGENTS.md가 에이전트 작업 성공률을 약 4% 높이고 버그를 35~55% 줄인 반면, LLM 자동 생성 지침 파일은 성공률을 낮추고 추론 비용을 20% 이상 늘렸다고 보고).

## Details: 원칙별 템플릿 적합성 평가

아래 평가는 "구조 기반 추정" 한계를 전제로 하며, 각 추정 항목에 **[확정 검증 필요]**를 표시한다.

### 1. 규칙 vs 판단 — 부분준수(추정)
비개발자가 "바이브 코딩"을 하는 사내 플랫폼 특성상, 안전을 위해 강한 규칙("반드시 ~하라", "절대 ~하지 마라")을 다수 넣었을 개연성이 높다. 안전·보안 영역(예: 프로덕션 배포, 시크릿 접근)에서는 강한 규칙이 **정당**하다(블로그도 "매우 중요한 영역은 예외"라고 명시). 그러나 코드 스타일·주석·문서화 같은 영역까지 경직된 규칙이 있다면 Claude 5 세대에서는 역효과다. **개선:** 안전 규칙과 스타일 규칙을 분리하고, 스타일은 "주변 코드를 따르라" 식으로 완화. **[확정 검증 필요]**

### 2. 예시 vs 인터페이스 설계 — 부분준수(추정)
AGENTS.md에 코드 예시 블록이 많다면 과잉 제약 위험. 다만 스택 고유의 "함정"(예: Cloudflare Worker에서 `node:fs` 등 node 전용 API 금지, Hono 라우팅에서 zod 검증 필수)은 예시보다 규칙/설명으로 두는 것이 적절하다. **개선:** "이렇게 짜라"는 긴 예시 코드보다, 잘 설계된 스크립트/명령(pnpm 스크립트, 검증 커맨드)과 간결한 설명으로 대체. **[확정 검증 필요]**

### 3. 프로그레시브 디스클로저 — 미준수 가능성 높음(추정, 최우선 개선 대상)
"AGENTS.md가 주요 에이전트 지침 소스"라는 구조 설명은 단일 대형 파일에 모든 지침을 넣는 구식 패턴일 가능성을 시사한다. 스택(React Router v7, Hono, Supabase, pnpm 모노레포)이 넓어 지침이 방대해지기 쉽다. 스킬/커맨드 폴더의 존재 여부가 불명확하다는 점도 미분리를 방증한다. **개선(핵심):** AGENTS.md는 "왜(Why)/무엇(What, 프로젝트 맵)/어떻게(How, 핵심 gotcha)"만 담아 100줄 안팎으로 줄이고, 작업별 지침(테스트 실행, DB 마이그레이션, 배포, 코드리뷰, Supabase RLS 등)을 `.claude/skills/<name>/SKILL.md`로 분리해 AGENTS.md에서 짧은 설명과 함께 참조. **[확정 검증 필요]**

### 4. 반복/중복 제거 — 미준수 가능성 높음(추정, 멀티 하네스 이슈)
Claude Code / Codex / Copilot 멀티 하네스를 지원한다는 점은, CLAUDE.md·AGENTS.md·`.github/copilot-instructions.md` 등에 **동일 내용이 복붙 중복**되어 있을 위험을 크게 높인다. 이는 유지보수 시 divergence(불일치)와 컨텍스트 오염을 유발한다. **개선:** AGENTS.md를 단일 소스(canonical)로 삼고, CLAUDE.md는 `@AGENTS.md` import 또는 심볼릭 링크(`ln -sf AGENTS.md CLAUDE.md`)로 참조, Copilot용 파일도 참조 방식으로, Codex는 config.toml로 설정을 분리. **[확정 검증 필요]**

### 5. 자동 메모리 — 해당 시 정보성
CLAUDE.md에 "이런 건 메모리에 저장하라"는 수동 지침이 있다면 제거 대상. 대부분의 템플릿은 이 부분을 명시하지 않으므로 낮은 우선순위. **[확정 검증 필요]**

### 6. 리치 레퍼런스 — 개선 여지(추정)
플랜/스펙을 단순 마크다운으로만 관리한다면, 테스트 스위트나 실제 코드 참조로 고도화 여지. 비개발자 사용자 특성상 이 항목은 우선순위가 낮으나, "정답 코드 예시 파일"을 레퍼런스로 두는 방식은 유효.

### 안전 훅 — 준수(강점)
`.claude/settings.json`과 `.githooks/`에 사전 구성된 안전 훅이 있다는 점은 **강점**이다. Claude Code의 PreToolUse/PostToolUse 훅은 컨텍스트 윈도우 밖에서 결정론적으로 작동하므로(예: PreToolUse에서 `permissionDecision: "deny"` + exit code 2로 도구 호출 차단), "규칙을 프롬프트로 반복 서술"하는 대신 훅으로 강제하는 것이 블로그 철학(판단은 모델에, 강제는 시스템에)과 정확히 부합한다. 비개발자 환경에서 `rm -rf`, 시크릿 접근, 임의 배포를 훅으로 차단하는 것은 프롬프트 규칙보다 훨씬 안전하다. **개선:** 프롬프트에 있는 "절대 하지 마라"류 안전 규칙 중 훅으로 이미 강제되는 것은 프롬프트에서 제거해 중복·오염을 줄여라. **[확정 검증 필요]**

## 잘 되어 있는 부분 (추정 강점)
- **AGENTS.md 단일 소스 지향:** 개방형 표준(AGENTS.md, 현재 Linux Foundation 산하 AAIF가 관리)을 주 지침으로 삼은 것은 멀티 하네스 이식성 측면에서 올바른 출발점.
- **안전 훅 사전 구성:** 비개발자 대상 플랫폼에서 시스템 레벨 가드레일은 필수적이고 모범적. 프롬프트 규칙보다 결정론적이고 우회 불가능.
- **명확한 스택 고정:** React Router v7 + Hono/CF Worker + Supabase + pnpm 모노레포로 스택을 고정한 것은 에이전트의 추론 부담을 줄인다.

## 개선이 필요한 부분과 구체적 수정 제안

### AGENTS.md 재구성 (권장 구조 — 100줄 안팎)
```
# 우미 코딩 에이전트 가이드
## Why  (이 레포가 무엇이고 무엇이 중요한가 — 2~3문장)
## What (프로젝트 맵)
- apps/web  — React Router v7 프론트엔드
- apps/api  — Hono / Cloudflare Worker
- packages/ — 공유 타입/유틸
- .claude/skills/ — 작업별 지침(필요 시 로드)
## How (핵심 gotcha만)
- 패키지 매니저는 pnpm (npm/yarn 금지)
- Worker에서 node: 전용 API 금지
- Supabase 접근은 RLS 전제
## 작업별 상세는 아래 스킬 참조
- 테스트: .claude/skills/testing/SKILL.md
- 배포: .claude/skills/deploy/SKILL.md
- 코드리뷰/검증: .claude/skills/verify/SKILL.md
- Supabase: .claude/skills/supabase/SKILL.md
```

### 스킬로 분리할 후보 (각 SKILL.md는 500줄 이하)
- **검증/코드리뷰 스킬** (블로그가 직접 예로 든 항목): 빌드·린트·타입체크·테스트를 순서대로 돌리고 실패 시 고치는 루프. Anthropic 내장 `/code-review`·`/verify` 스킬 활용 가능.
- **Supabase 스킬:** 마이그레이션, RLS 정책, 인증 흐름 — Supabase 공식 `supabase/agent-skills` 재사용 가능(`npx skills add supabase/agent-skills`).
- **배포 스킬:** Cloudflare Worker 배포 절차 및 wrangler 환경변수.
- **테스트 스킬:** Vitest/Playwright 실행 규약.

### 멀티 하네스 중복 제거
- AGENTS.md = 단일 진실 원천.
- CLAUDE.md → `@AGENTS.md` import 한 줄, 또는 심볼릭 링크(`ln -sf AGENTS.md CLAUDE.md`). ※ Windows 팀원이 있으면 심볼릭 링크 대신 import 또는 pre-commit 복사 훅 사용.
- Copilot(`.github/copilot-instructions.md`) → AGENTS.md 참조.
- Codex → 추가 설정은 `config.toml`에만.

## Recommendations (우선순위별, 비개발자 실행 가능)

**즉시 (1일 이내):**
1. **`/doctor` 실행.** Claude Code에서 레포를 열고 `/doctor`를 실행하면 스킬·CLAUDE.md 과잉을 자동 진단·정리해준다. 비개발자도 실행 가능하며, 실제 파일 접근이 안 되는 본 평가의 한계를 직접 메워준다. *(기준: 진단 결과 제거 제안이 나오면 검토 후 반영)*

**단기 (1주 이내):**
2. **AGENTS.md 100줄 안팎으로 축소.** 위 권장 구조로 재작성. "파일시스템만 봐도 아는 것"과 훅으로 이미 강제되는 규칙은 삭제.
3. **작업별 지침을 스킬로 분리.** 최소 검증·배포·Supabase·테스트 4종을 `.claude/skills/`로. 각 SKILL.md는 500줄 이하.
4. **멀티 하네스 중복 제거.** CLAUDE.md·Copilot 파일을 참조 방식으로 전환.

**중기 (1개월 이내):**
5. **충돌 규칙 감사.** "절대/반드시" 표현을 전수 조사해 안전(훅으로 이관)·스타일(완화)로 분류. arXiv:2606.15828의 "Conflicting Instructions/Init Fossilization" 스멜 체크리스트 참고.
6. **검증 루프 스킬화.** 비개발자가 실수해도 에이전트가 스스로 테스트·수정하도록.

**개선 판단 기준(벤치마크):**
- ① AGENTS.md가 **150줄을 넘으면** 스킬 분리 신호.
- ② 동일 문장이 **2개 이상 파일**에 존재하면 중복 제거 신호.
- ③ `/doctor`가 제거를 제안하면 반영.
- ④ 에이전트가 **같은 실수를 2회 반복**하면 해당 지침을 스킬/AGENTS.md에 추가(Anthropic 권장 업데이트 트리거).

## Caveats
- **레포 직접 접근 실패:** 본 평가는 실제 파일 내용을 인용하지 못했다. git clone·GitHub API·raw·검색 모두 실패했으며(비공개 또는 미인덱싱 추정), 모든 "[확정 검증 필요]" 항목은 `/doctor` 실행 및 파일 육안 확인으로 확정해야 한다. 공개 여부를 확실히 하려면 인증된 환경에서 `curl -i https://api.github.com/repos/team-smartcon-tech/woomi-coding-agent-template`로 HTTP 상태(404=비공개/부재, 200=공개)를 확인하면 된다.
- **블로그 수치의 출처:** "80% 제거, 성능 손실 없음"은 Anthropic 자체 코딩 평가 기준의 자체 보고 수치이며(보도 기준 약 800→164토큰), 어떤 작업 범주가 유지/약화됐는지 세부 분해는 공개되지 않았다.
- **모델 세대 전제:** 이 규칙들은 Claude Opus 5 / Fable 5 / Sonnet 5 등 Claude 5 세대 기준이다. 구세대 모델을 쓰는 사용자에게는 일부 가드레일이 여전히 유효할 수 있다.
- **안전 우선 예외:** 비개발자 대상 플랫폼에서는 "규칙을 줄여라"를 안전 영역까지 무분별하게 적용하면 안 된다. 안전·보안은 강한 규칙 또는 훅으로 유지하는 것이 옳다.
